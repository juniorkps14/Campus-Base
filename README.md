# Campus CMS — ภาพรวมระบบ (1 แผ่น)

**ระบบเว็บไซต์และระบบจัดการเนื้อหา วิทยาลัยเทคนิคกาฬสินธุ์** · www.ktc.ac.th · รุ่น 1.0 LTS (tag `v1.0-lts`)
เริ่มพัฒนา 8 พ.ย. 2569 · ใช้งานจริง 9 พ.ย. 2569 · แทนที่ Directus/ktc-web และ CMS-KTC (PHP)

---

## 1. เป้าหมายและโจทย์

| โจทย์ | สิ่งที่ออกแบบรองรับ |
|---|---|
| ใช้งานยาว ~10 ปี | เลือกเทคโนโลยีเสถียร dependency น้อย (Go ใช้ library เพียง 4 ตัว) มีเอกสารส่งมอบครบ |
| เจ้าหน้าที่ปรับแต่งเองได้ | ตกแต่งสี/ฟอนต์/หน้าแรกจากหลังบ้าน ไม่ต้องเขียนโค้ด |
| หน่วยงานอื่นนำไปใช้ได้ | ไม่ผูกกับวิทยาลัย เพิ่ม collection ใหม่ได้ในไฟล์เดียว |
| ไม่ใช้ PHP/MySQL | ใช้ Go + PostgreSQL |
| ลิงก์เว็บเดิมต้องไม่เสีย | ระบบ redirect แก้ได้จากหลังบ้าน |

## 2. สถาปัตยกรรม

```
 ผู้ใช้ ─► Reverse proxy (HTTPS, Cloudflare/NPM) ─► web  Nuxt 4 SSR   หน้าเว็บ + /admin (ธีมเดียวกัน)
                                                      │  /api/** /media/** ส่งต่อภายใน
                                                      ▼
                                                     api  Go 1.26      REST · ล็อกอิน · ไฟล์/ย่อรูป · กรอง HTML · SSO
                                                      ▼
                                                     db   PostgreSQL 18
                                                     backup  สำรองข้อมูลเข้ารหัส (container แยก)
```

เบราว์เซอร์คุยกับ **โดเมนเดียว** เสมอ → cookie เป็น first-party, ไม่ต้องตั้ง CORS, ตั้ง proxy จุดเดียว
มีเพียงพอร์ตของ web ที่เปิดออก ส่วน api และ db อยู่ในเครือข่าย docker ภายใน

## 3. Technology ที่ใช้

| ส่วน | เทคโนโลยี | เหตุผลที่เลือก |
|---|---|---|
| web | **Nuxt 4** (Vue 3, SSR) | หน้าเว็บ render ที่เซิร์ฟเวอร์ เร็วและติดอันดับค้นหาได้ดี หลังบ้านอยู่ในแอปเดียวกัน ใช้ธีมเดียว deploy ครั้งเดียว |
| api | **Go 1.26** + pgx | ไบนารีเดียว ไม่มี runtime ให้ดูแล กินหน่วยความจำน้อย compile-time type check อ่านและส่งต่อได้ง่าย |
| db | **PostgreSQL 18** | jsonb เก็บบล็อกเนื้อหาและธีม · view กรองข้อมูลเผยแพร่ · recursive query สำหรับหน้าลำดับชั้น · `pg_trgm` ค้นหาภาษาไทย |
| backup | shell + เข้ารหัส AES-256 | สำรอง DB รายวัน + full รายสัปดาห์ ส่งปลายทางด้วย SSH |
| deploy | Docker Compose | ติดตั้ง ~5 นาที ย้ายเครื่องได้โดยไม่ต้องใช้ git |

## 4. แนวคิดในการสร้าง

1. **Resource engine (schema-driven)** — ประกาศ collection ครั้งเดียวใน `api/internal/server/resources.go` ได้ครบอัตโนมัติ: API (สร้าง/แก้/ลบ/ค้นหา/กรอง/เรียง/แบ่งหน้า), API สาธารณะจาก view, และหน้าหลังบ้าน (ตาราง ฟอร์ม ตัวกรอง เมนู) engine ประมาณ 600 บรรทัด ชื่อคอลัมน์มาจาก registry และค่าทุกค่าส่งเป็น parameter จึงไม่มีช่อง SQL injection
2. **เนื้อหาเป็นบล็อก JSON ไม่ใช่ HTML ก้อนเดียว** — 16 ชนิด (ข้อความ หัวข้อ รูป แกลเลอรี ไฟล์แนบ วิดีโอ ฝังแผนที่ ปุ่ม การ์ด รายการเอกสาร บุคลากร ข่าวล่าสุด ฯลฯ) จัดหน้าบนมือถือได้ดี เปลี่ยนดีไซน์ทั้งเว็บได้โดยไม่แตะเนื้อหา กรองความปลอดภัยทีละช่องได้
3. **หลังบ้านกับหน้าบ้านเป็นแอปเดียว** — ใช้ธีม ฟอนต์ สีเดียวกัน หลังบ้านเปลี่ยนสีตามธีมเว็บ
4. **ธีมเป็นข้อมูล ไม่ใช่โค้ด** — สี 12 ชุด ฟอนต์ เลย์เอาต์ จัดเรียงหน้าแรก พรีวิวสด ย้อนกลับได้ 20 เวอร์ชัน
5. **Security by default** — ดูหัวข้อ 6
6. **Additive migration** — ไฟล์ `api/migrations/NNN_*.sql` รันอัตโนมัติตอน api เริ่ม (ทีละไฟล์ใน transaction) ห้ามแก้ไฟล์เก่า ให้เพิ่มไฟล์ใหม่เสมอ ทำให้ย้อนกลับ image เก่าได้ปลอดภัย

## 5. ความสามารถหลัก

- **เนื้อหา**: ข่าว/ประกาศ (หมวดหมู่ ปักหมุด ข่าวเด่น ตั้งเวลาเผยแพร่ ยอดเข้าชม) · หน้าเนื้อหาลำดับชั้น (ฝ่าย → งาน → หน้าย่อย) · หน่วยงาน/แผนกวิชา · บุคลากรรายบุคคล · ทำเนียบผู้บริหารแบบผัง · คลังเอกสาร (ITA, แบบฟอร์ม) · สไลด์/ป๊อปอัป · กิจกรรม · รางวัล · ฟอร์มติดต่อ
- **เว็บ**: เมนู 3 ชั้น (mega menu) · ค้นหาทั้งเว็บ · sitemap.xml/robots.txt อัตโนมัติ · SEO · ตัวนับผู้เข้าชม · เอฟเฟกต์เทศกาล · ศูนย์รวมโซเชียล
- **หลังบ้าน**: สิทธิ์ admin / editor / หน่วยงาน (dept) · ประวัติเวอร์ชัน · ทำซ้ำ · จัดการเป็นชุด (bulk) · audit log
- **ศูนย์บัญชีกลาง (SSO / OpenID Connect)**: บัญชีเดียวเข้าทุกระบบของวิทยาลัย (E-DOC, meet, hotel, ask, board, lab, converter ฯลฯ) หน้า `/admin/sso` กำหนดสิทธิ์ผู้ใช้ × ระบบ, role ต่อระบบ, บันทึกการเข้าใช้ และสแกนค้นหาระบบใหม่ในเครือข่ายอัตโนมัติ

## 6. ความปลอดภัย

| ภัย | การป้องกัน |
|---|---|
| XSS | กรอง HTML ฝั่งเซิร์ฟเวอร์ด้วย bluemonday ทุกช่อง จำกัดชนิดลิงก์ ทิ้งบล็อกชนิดที่ไม่รู้จัก |
| CSRF | ต้องมี header `X-CMS: 1` + cookie SameSite=Lax + ไม่เปิด CORS |
| เดารหัสผ่าน | argon2id · จำกัดครั้งต่อ IP และต่อชื่อผู้ใช้ · เวลาตอบเท่ากัน |
| Session | token สุ่ม 256 บิต เก็บ sha256 ใน DB → logout/เปลี่ยนรหัส/ปิดบัญชีมีผลทันที |
| ไฟล์อันตราย | whitelist นามสกุล + ตรวจ magic bytes · ไม่รับ SVG/HTML · เสิร์ฟด้วย CSP sandbox + nosniff |
| ปลอม IP | web เขียนทับ `x-client-ip` เสมอ |
| container | api/web read-only + `no-new-privileges` · api เป็น distroless non-root · db/api ไม่เปิดพอร์ตออกนอก |
| ตรวจย้อนหลัง | ทุกการแก้ไข อัปโหลด ล็อกอิน บันทึกใน `audit_log` |

## 7. ทำไมใช้งานได้รวดเร็ว

### 7.1 ความเร็วต่อผู้เข้าชม
| กลไก | ผล |
|---|---|
| **SSR + cache 60 วินาที** | หน้าสาธารณะ render ที่เซิร์ฟเวอร์ ส่ง HTML สำเร็จรูป และ **ล้าง cache ทันทีเมื่อแก้จากหลังบ้าน** ได้ทั้งเร็วและทันสมัย |
| **เรียก `/api/site` ครั้งเดียวต่อหน้า** | ได้ settings + theme + menus ชุดเดียว ทุกคอมโพเนนต์ใช้ร่วมกัน |
| **Go + PostgreSQL** | ตอบสนองเร็ว ใช้ทรัพยากรน้อย ข้อมูลสาธารณะอ่านจาก view ที่กรองสถานะเผยแพร่ไว้แล้ว |
| **รูป AVIF อัตโนมัติ** | เลือกรูปตาม header `Accept` ของเบราว์เซอร์ ย่อรูปและเก็บ cache ถ้าแปลงไม่ทันใน 2.5 วินาที ส่ง JPEG แทน ไฟล์เล็กลง โหลดเร็ว |
| **หลังบ้านเป็น SPA** | เข้าสู่ระบบแล้วสลับหน้าโดยไม่โหลดทั้งหน้าใหม่ |
| **ลิงก์เก่าไม่ตาย** | ไม่พบหน้า → ถาม `/api/redirect` ก่อนแสดง 404 |

### 7.2 ความเร็วในการพัฒนาและดูแล
| กลไก | ผล |
|---|---|
| Resource engine | เพิ่มข้อมูลชนิดใหม่ได้ในไฟล์เดียว ไม่ต้องเขียนหน้า CRUD ซ้ำ |
| นำเข้าข้อมูลเดิม | `tools/import_ktc.py` ย้ายเนื้อหาจากเว็บเก่าเข้ามาได้ |
| Compose คำสั่งเดียว | `docker compose up -d --build` ติดตั้งเสร็จ ~5 นาที |
| Staging แยก | ทดสอบจากข้อมูลสำรองก่อนขึ้นจริง แล้วทิ้งได้ |
| ย้อนกลับเร็ว | เก็บ image รุ่นก่อน + backup ก่อน deploy ทุกครั้ง |
| เอกสารครบ | admin-guide · deploy · operations · backup · moving · handover · identity · sso |

> **หมายเหตุ**: เอกสารนี้อธิบายกลไกที่ทำให้เร็วตามการออกแบบ ยังไม่มีตัวเลขวัดจริง (เวลาโหลด, Lighthouse, จำนวนผู้ใช้พร้อมกัน) หากต้องการนำเสนอเป็นตัวเลข ควรวัดบน www.ktc.ac.th ก่อน

## 8. การดำเนินงานและการส่งมอบ (LTS 1.0)

- **LTS = ไม่เพิ่มฟีเจอร์** เน้นเสถียรภาพ
- สำรอง DB รายวัน + full รายสัปดาห์ เข้ารหัส AES-256 ส่งปลายทางด้วย SSH
- มี housekeeping อัตโนมัติ และคำสั่ง `/api set-password` สำหรับตั้งรหัสผ่านผู้ดูแล
- ย้าย container แยกเครื่องได้ (`deploy/split/*.compose.yaml`)
- โดเมนและ Cloudflare เป็นส่วนกลาง ไม่ผูกกับระบบนี้

## 9. โครงสร้างโฟลเดอร์

```
api/            Go — cmd/server, internal/server, migrations/*.sql

backup/         สคริปต์สำรองข้อมูล
deploy/         ชุด compose สำหรับแยกเครื่อง
tools/          backup, import_ktc.py, handover.sh ฯลฯ
docs/           เอกสารทั้งหมด
```
